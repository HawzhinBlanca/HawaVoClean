# HawaVoClean — Resolve / desktop shell

The Electron shell that hosts the HawaVoClean web UI inside **DaVinci Resolve Studio** (as a
Workflow Integration plugin) or as a plain desktop window, and that owns the lifetime of the
Python engine (`hawavoclean serve`). It is the "Resolve / desktop shell" part of
[`docs/ui-contract.md`](../docs/ui-contract.md) (sections 3, 4 and 5 are binding).

```
resolve-plugin/
  com.hawavoclean.resolve/    shell sources — what gets copied into the plugin directory
    manifest.xml              Resolve plugin manifest (id com.hawavoclean.resolve, entry main.js)
    package.json              name/main/scripts; exact Electron 43.4.1 for controlled standalone tests
    main.js                   main process: security boundary, engine, IPC, Resolve bridge, shutdown
    preload.js                sandboxed preload: exposes window.hawa (HawaBridge) via contextBridge
    session-auth.js           exact-origin session bootstrap and Authorization-header policy
    engine.json.example       template for engine.json (generated by install.sh)
  install.sh                  locked build → immutable stage → real lifecycle test → optional activation
  activate.sh                 build-tool-free transactional activation and rollback (safe for sudo)
  dev/fake-engine.mjs         stand-in for `hawavoclean serve` (Node, no deps) for shell testing
  dev/selftest.sh             headless Electron smoke test (ok / crash / hang / stubborn engine)
  dev/stage-selftest.sh       exact staged Electron → bundled engine → health/auth/shutdown proof
scripts/build_resolve_engine.py
                              exact wheel → relocatable macOS arm64 CPython 3.11 engine bundle
```

Nothing generated is committed: `node_modules/`, `engine.json`, `WorkflowIntegration.node`,
`index.html` and `assets/` are gitignored inside `com.hawavoclean.resolve/`; the assembled plugin
lives under `build/` (gitignored).

## How it works

1. **Resolve launches the plugin** in the Electron/Chromium runtime owned and shipped by the installed
   DaVinci Resolve version, using `manifest.xml` → `main.js`. HawaVoClean does not infer that vendor
   runtime's version from its standalone test dependency. The controlled test runtime is exact
   Electron 43.4.1; real-host version evidence is captured separately during Resolve acceptance.
2. **`main.js` reads `engine.json`** (next to itself):
   `{"command":["./engine/hawavoclean-engine","serve"],"cwd":".","env":{"PYTHONNOUSERSITE":"1","PYTHONDONTWRITEBYTECODE":"1"}}`
   and spawns
   `command + ["--port","0","--token-stdin","--ui-dir",<plugin dir>]` and sends a fresh random 32-hex
   bootstrap secret through a one-shot stdin pipe (never the process command line). It waits for
   the engine's single stdout line `{"event":"ready","port":N,"pid":P,"version":V}`
   (timeout 60 s). On failure (spawn error, early exit, timeout) the window shows an error page
   with the command and the engine's stderr tail. `/opt/homebrew/bin`, `/usr/local/bin` and the
   engine's own bin directory are prepended to `PATH` for the child, so `ffmpeg` is found even
   though GUI-launched processes inherit a minimal PATH. Main exchanges that secret at
   `POST /api/session`; the root secret and renewable short-lived Bearer capability remain in main.
   The renderer receives only `{baseUrl}`. Main injects Authorization only on the exact spawned
   origin's `/api/**` requests (including audio and SSE) and blocks renderer access to `/api/session`.
3. **`WorkflowIntegration.node` is required in main** (a sandboxed preload cannot load native
   modules). `InitializePromise('com.hawavoclean.resolve')` succeeding ⇒ `host = 'resolve'`,
   the `ResolveQuit` callback is registered (→ quit) and the `resolve` bridge is exposed. If the
   module is missing, fails to load, or Resolve is not running (Initialize rejects within ~300 ms,
   hard cap 8 s) ⇒ `host = 'electron'` and no `resolve` bridge — the same shell doubles as the
   desktop app.
4. **The window** (1280×820, min 960×640, background `#0e1013`, `sandbox:true`,
   `contextIsolation:true`, `nodeIntegration:false`) loads `index.html` — the Vite bundle copied
   from `ui/dist` at assembly time. `preload.js` exposes `window.hawa` exactly as `HawaBridge`
   (`ui/src/bridge/types.ts`): `host`, credential-free `engine.getEndpoint()`, `files.pickAudio()`,
   asynchronous `files.registerDroppedFile(file)`, a fail-closed legacy `files.pathForFile()` that
   always returns `null`, and `files.revealInFinder(path)`,
   and — only when `host === 'resolve'` — `resolve.getSelectedClip/importMedia/replaceClip/
   appendToTimeline/getContext`. Everything is `ipcRenderer.invoke` on the contract's channel names
   (`hawa:engine:endpoint`, `hawa:files:pick|register-dropped|reveal`, `hawa:resolve:selected|import|
   replace|append|context`); the single synchronous call `hawa:host` gives the preload `host` as a
   plain value. Handler errors surface as `Error(message)` in the renderer.
   Main root-registers every file-picker path and every Resolve-selected clip before it returns the
   path. A dropped file is registered synchronously through main IPC before use, or uploaded into
   broker-managed storage when registration is unavailable. The accepted native formats are exactly
   WAV/WAVE, AIF/AIFF/AIFC, FLAC, MP3, M4A and MP4.
5. **Resolve API mapping** (promise flavour via `GetResolvePromise()`, calls awaited sequentially):
   `getSelectedClip` → `MediaPool.GetSelectedClips()[0]`, else current timeline's
   `GetCurrentVideoItem().GetMediaPoolItem()`; `importMedia(path)` → `MediaPool.ImportMedia([path])[0]`;
   `replaceClip(mediaId, path)` → `ReplaceClipPreserveSubClip(path)`, fallback `ReplaceClip(path)`;
   `appendToTimeline(mediaId)` → `MediaPool.AppendToTimeline([item])`; `getContext()` →
   `{project: Project.GetName(), timeline: Timeline.GetName(), page: Resolve.GetCurrentPage()}`.
   A `MediaPoolItem` is found by `mediaId` from a small cache of items already handed out, then the
   current selection, then a full walk of `GetRootFolder()` (`GetClipList()` / `GetSubFolderList()`).
   `ResolveClip.durationS` is derived from `GetClipProperty('Duration')` + `'FPS'` when parsable.
6. **Shutdown** (`before-quit`, window closed, `ResolveQuit`, SIGINT/SIGTERM): main sends
   `POST /api/shutdown` with its bootstrap header, waits ≤1 s, then `SIGTERM`, then `SIGKILL`
   after 3 s; finally
   `WorkflowIntegration.CleanUp()`. A 10 s hard deadline forces `app.exit`.

Checked empirically with exact standalone Electron 43.4.1 (see `dev/selftest.sh`): from the `file://` page,
`<script type="module">`, dynamic `import()`, ES-module workers (with imports), classic workers,
`OffscreenCanvas` and WebGL2 inside a worker all work, and `fetch` to `http://127.0.0.1:<port>`
succeeds with the engine's CORS headers.

## Requirements

* macOS, **DaVinci Resolve Studio** 20.1 or newer (the free edition does not load Workflow
  Integration plugins; promise APIs need 20.1+; developed against 21.0.3). The SDK must be present at
  `/Library/Application Support/Blackmagic Design/DaVinci Resolve/Developer/Workflow Integrations/`
  (it is installed with Resolve Studio) — `install.sh` copies
  `Examples/SamplePlugin/WorkflowIntegration.node` (universal arm64 + x86_64) from there.
* A clean, provenance-bearing HawaVoClean wheel and the relocatable engine bundle produced from it by
  `scripts/build_resolve_engine.py`. The bundle contains an isolated CPython 3.11 runtime, the exact
  locked `studio` + `ui` dependency closure, the exact wheel, integrity manifests and the third-party
  license inventory. It is qualified for Apple silicon macOS in v3.3.
* `ffmpeg` on `/opt/homebrew/bin` or `/usr/local/bin` (external runtime prerequisite).
* Node plus a bootstrap npm capable of reading lockfile v3. The installer uses that npm only to
  integrity-check and install `resolve-plugin/toolchain/package-lock.json`, then performs all UI and
  shell work with the lock's exact pnpm 11.22.0. npm is not part of the runtime or build tool closure.

## Install into Resolve

From a clean exact release revision, first build the wheel and then its self-contained engine:

```bash
uv build
uv run python scripts/build_resolve_engine.py \
  --wheel "$PWD/dist/hawavoclean-3.3.0-py3-none-any.whl" \
  --output "$PWD/build/resolve-engine"
resolve-plugin/install.sh --engine-bundle "$PWD/build/resolve-engine"
```

Useful assembly modes:

```bash
resolve-plugin/install.sh --engine-bundle /absolute/engine --no-install
resolve-plugin/install.sh --engine-bundle /absolute/engine --skip-ui-build --no-install
resolve-plugin/install.sh --engine-bundle /absolute/engine --desktop-only --dest /absolute/disposable/plugins
resolve-plugin/install.sh --engine-bundle /absolute/engine --sdk-node /absolute/WorkflowIntegration.node
```

The installer bootstraps its exact package managers from a committed integrity lock, accepts only
locked inputs, assembles a content-addressed stage under
`build/resolve-plugin/stages/`, verifies all engine bytes, runs `doctor`, and exercises the real staged
Electron → session bootstrap → main-authenticated health → shutdown lifecycle before activation. The
stage contains shell files, UI assets, the native bridge, the complete `engine/`, and signed inventories
`SHA256SUMS`/`SYMLINKS` plus identity markers.

The default Resolve plugin directory is normally root-owned. In that case the unprivileged installer
stops with exit code 2 and prints one exact `sudo resolve-plugin/activate.sh ...` command. The activator
uses a same-filesystem transaction: verify copy, preserve the prior owned plugin, atomic rename, verify
again, and rollback after any failure or interrupt. It refuses unknown targets and a running Resolve.

Then **restart DaVinci Resolve Studio** (plugins are enumerated at startup) and open
**Workspace → Workflow Integrations → HawaVoClean**.

`engine.json` points only inside the installed plugin. The installed runtime has no source-checkout or
mutable virtual-environment dependency and may be relocated as a unit. It suppresses bytecode writes,
so normal execution does not mutate the content-addressed engine and works from a read-only install.

## Run standalone (desktop, no Resolve)

```bash
(cd resolve-plugin/com.hawavoclean.resolve && \
  node ../toolchain/node_modules/pnpm/bin/pnpm.mjs install --frozen-lockfile)
resolve-plugin/install.sh --engine-bundle /absolute/engine --desktop-only --no-install
HAWA_DEVTOOLS=1 resolve-plugin/com.hawavoclean.resolve/node_modules/.bin/electron \
  /absolute/content-addressed/stage/com.hawavoclean.resolve
```

With no `index.html` next to `main.js` the window shows a "UI bundle not found" page; copy
`ui/dist/*` next to `main.js`, or run the assembled plugin directly:

```bash
resolve-plugin/install.sh --engine-bundle /absolute/engine --desktop-only --no-install
resolve-plugin/com.hawavoclean.resolve/node_modules/.bin/electron /absolute/staged/com.hawavoclean.resolve
```

Without Resolve the bridge reports `host: 'electron'` and has no `resolve` sub-object.

Environment knobs: `HAWA_DEVTOOLS=1` (open DevTools), `HAWA_SELFTEST=1` (headless smoke test:
load the UI, call `window.hawa.engine.getEndpoint()` and `/api/health` from the renderer, print
`HAWA_SELFTEST_RESULT {...}` to stdout, quit), `HAWA_ENGINE_TIMEOUT_MS` (override the 60 s ready
timeout; tests only).

## Electron security boundary

The shell runs the UI on a private, in-memory `hawa://app` origin rather than `file://` or a shared
Resolve session. The protocol handler serves only canonical files below the installed plugin;
renderer traffic is filtered to those files and the one authenticated loopback engine port. CSP,
sandboxing, context isolation, exact-sender IPC checks, synchronous permission denial and total
navigation/popup/webview denial are exercised by the lifecycle self-tests.

The exact standalone test runtime (Electron 43.4.1) is HawaVoClean-owned and lock-audited. Resolve's
embedded runtime is Blackmagic-owned and must be captured separately; the installed Resolve 21.0.3
currently contains Electron 36.3.2 with known advisories. See
[`docs/resolve-runtime-risk.md`](../docs/resolve-runtime-risk.md). That vendor risk remains pending
explicit user acceptance and must never be reported as a clean dependency scan.

## Testing the shell without the Python engine

```bash
resolve-plugin/dev/selftest.sh              # all scenarios
resolve-plugin/dev/selftest.sh ok crash     # subset
```

`dev/fake-engine.mjs` implements the slice of the engine contract the shell relies on (ready line,
`/api/session`, Bearer-authenticated `/api/health`, `/api/shutdown`, CORS, static `--ui-dir`).
`FAKE_ENGINE_MODE=ok|crash|hang|stubborn`
exercises the happy path, early crash (error page with stderr tail), ready timeout, and a child that
ignores `/api/shutdown` + `SIGTERM` (the shell must `SIGKILL` it). The script checks that the engine
pid is gone after Electron quits (no orphans).

## Troubleshooting

* **Plugin not listed under Workspace → Workflow Integrations** — Resolve *Studio* is required;
  the plugin directory must be under the path above with `manifest.xml` at its top level; restart
  Resolve after installing; check the files are world-readable (`sudo chmod -R a+rX …/com.hawavoclean.resolve`).
* **"The HawaVoClean engine could not be started"** — read the stderr tail on the page. Typical
  causes are a damaged/incomplete install or missing external `ffmpeg`. Re-run the locked installer;
  do not repair the production install by pointing it at a development virtual environment.
* **The UI says host is `electron` while running inside Resolve** — `WorkflowIntegration.node` is
  missing from the plugin directory (re-run `install.sh`), or `Initialize` failed (Resolve Free, or
  Resolve denied the plugin id). A standalone launch always reports `electron`.
* **Blank/dark window** — open DevTools (`HAWA_DEVTOOLS=1` standalone; inside Resolve use the
  View menu of the plugin window) and look for failed asset loads: `index.html`/`assets/` must sit
  next to `main.js` and be built with Vite `base: './'`.
* **Something still listening after quit** — the shell posts `/api/shutdown`, then SIGTERM, then
  SIGKILL; if Electron itself was killed with `kill -9`, the engine may outlive it:
  `pkill -f 'hawavoclean serve'`.
* **Dock/menu says "Electron"** — expected: the plugin runs inside Resolve's bundled Electron runtime.
* **Firewall prompts** — none expected; the engine binds `127.0.0.1` only. The root bootstrap secret
  is random per launch, and renderer sessions are short-lived and memory-only.
